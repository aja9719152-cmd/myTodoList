## 2. 확인이 필요한 작업 🔍

가상 브라우저(jsdom)와 헤드리스 Chrome으로는 확인하지 못한 항목이다.

- 🔍 **Alt+D 충돌:** Chrome·Firefox에서 원래 주소창 이동 단축키인 Alt+D를 앱이 실제로 가로채는지
- 🔍 **애니메이션 체감:** 추가·삭제·완료 슬라이드, 테마 전환이 실제 브라우저에서 자연스러운지
- 🔍 **드래그 앤 드롭 체감:** 마우스·터치로 끌 때의 느낌, 화면 끝 자동 스크롤 속도
- 🔍 **휴대폰 화면:** 480px 이하 레이아웃 (Windows Chrome은 창 최소 너비 때문에 재현 불가)
- 🔍 **태블릿 터치:** 두 번 탭으로 수정, 손잡이 끌기 (현재는 ✎ 버튼으로 수정 가능)
- 🔍 **대화상자 모양:** 실제 `<dialog>`의 모습과 포커스 이동 (테스트에서는 가짜 동작으로 대신함)
- 🔍 **실제 브라우저 속도:** 할 일 300개 이상에서의 반응 속도

## 3. 남은 작업 · 개선 후보 ⬜

### 대화 중 제안했던 항목
- ⬜ **가져오기 시 자동 분류:** 카테고리가 없는 파일을 가져오면 "개인" 대신 키워드로 분류 (옵션)
- ⬜ **1024px 기준 조정:** 너비 1024px 창은 스크롤바 때문에 실제 폭이 약 1002px이라 1단으로 보임. 기준을 낮출지 결정 필요

### 알려진 제약
- ⬜ **노트북 화면 메뉴 고정:** 1024~1439px에서는 왼쪽 메뉴가 고정되지 않아 스크롤하면 사라짐 (현재는 Alt+1~4로 필터 전환 가능)
- ⬜ **좁은 화면 단축키 안내:** 1024px 미만에서는 단축키 안내 패널이 없고 버튼 툴팁으로만 확인 가능
- ⬜ **편집 중 다른 버튼 클릭:** 편집하다가 다른 버튼(예: 삭제)을 누르면 편집 저장이 먼저 일어나 화면이 바뀌므로, 그 버튼을 한 번 더 눌러야 할 수 있음
- ⬜ **인라인 수정 시 자동 분류:** 현재는 새로 추가할 때만 동작

### 제안 (대화에서 결정되지 않음)
- ⬜ **자동화 테스트 저장소 포함:** 개발 중 쓴 jsdom 테스트는 임시 폴더에만 있음. `tests/`로 옮기면 이후 변경 때 회귀 확인이 쉬워짐
